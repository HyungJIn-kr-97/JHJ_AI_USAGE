# 표시 데이터 저장소 — 읽는 쪽 계약

앱이 팝업에 보여 주는 값을 **다른 도구가 그대로 읽어 쓸 수 있게** 파일로 남깁니다.
쓰는 쪽 구현은 [DisplayDataStore.cs](../200.Source/costats.App/Services/DisplayDataStore.cs) 한 곳이고,
이 문서가 **구조·칸의 의미·갱신 주기의 정본**입니다.

---

## 1. 어디에 있나

```text
%LOCALAPPDATA%\AiUsageMonitor\data\
  snapshot.json                       ← 지금 화면에 떠 있는 값 전부. 읽는 쪽의 기본 진입점입니다
  timeline\<key>\<YYYY-MM>.jsonl      ← 시점 단위 이력. 한 줄 = 한 갱신
```

- 설치 폴더(`…\AiUsageMonitor\app`) **밖**입니다 — 앱이 업데이트돼도 지워지지 않습니다.
- 같은 폴더의 `history\` 는 **다른 저장소**입니다(`UsageHistoryStore`). 그쪽은 날짜×모델 사용량만 갖습니다.
- 이 PC 안에만 있고 **어디로도 전송하지 않습니다.** 메일 주소·계정 UUID 가 그대로 들어 있으니
  파일을 남에게 보낼 때는 `account` 블록을 지우거나 가려 주십시오.

## 2. 언제 쓰이나

- **갱신이 끝날 때마다** 씁니다(설정 › 일반 「갱신 주기」, 기본 5분). 갱신 **도중**에는 쓰지 않습니다 —
  그때는 계정 하나만 실려 와 반쪽이 되기 때문입니다.
- `snapshot.json` 은 매번 **통째로 덮어씁니다.** 임시 파일에 쓰고 바꿔 끼우므로 읽는 쪽이 반쪽 JSON 을 보지 않습니다.
- `timeline` 은 **값이 달라졌을 때만** 한 줄 더합니다 — 갱신 시각만 다른 줄은 쌓지 않습니다.
- 13개월이 지난 월 파일은 지웁니다.

## 3. snapshot.json

```jsonc
{
  "schemaVersion": 1,            // 구조가 호환되지 않게 바뀌면 올라갑니다. 읽는 쪽은 이 값을 먼저 보십시오
  "app": "1.0.3.20261008",       // 쓴 앱의 버전
  "generatedAt": "2026-10-08T14:05:03.1+09:00",   // 이 파일을 쓴 시각
  "refreshedAt": "2026-10-08T14:05:02.9+09:00",   // 화면 머리줄의 「갱신」 시각
  "nextRefreshAt": "2026-10-08T14:10:02.9+09:00", // 머리줄의 「다음」 시각. 예약이 없으면 없음
  "accounts": [ /* 계정 카드 하나당 한 칸 */ ]
}
```

### 3-1. `accounts[]` — 카드 한 장

| 칸 | 뜻 |
|---|---|
| `key` | 파일 이름으로 쓰는 식별자. `providerId` 에서 영숫자·`-`·`_` 외를 `-` 로 바꾼 것입니다 |
| `providerId` | 앱 안의 계정 ID. `claude` · `claude:work` · `codex` 꼴입니다 |
| `providerKind` | `claude` · `codex` · `copilot` · `gemini` |
| `account` | **계정 단위** — 갱신해도 거의 바뀌지 않는 값 |
| `point` | **시점 단위** — 갱신마다 바뀌는 값. `timeline` 에 쌓이는 것과 같은 모양입니다 |
| `usage` | 선택한 기간의 사용량 원자료 |

### 3-2. `account` — 계정 단위

| 칸 | 타입 | 뜻 |
|---|---|---|
| `displayName` | string | 카드 제목. 설정에서 정한 명칭이고, 안 정했으면 메일의 `@` 앞 |
| `accountType` | string? | 「회사」·「개인」 등 유형 딱지. 안 정했으면 없음 |
| `email` | string? | 로그인 메일 **전문** |
| `uuid` | string? | Claude 계정 UUID. Claude 가 아니거나 로그인 전이면 없음 |
| `organization` | string? | 조직명 |
| `plan` | string? | 화면의 플랜 칩 문구 (`Max · $200/mo` 꼴) |
| `planTier` | string? | 서비스가 준 등급 코드 (`default_raven` · `default_claude_max_20x` 등) |
| `monthlyFeeUsd` | number? | 월 구독료(USD). 활용도 계산의 분모입니다 |
| `feeIsEstimate` | bool | `true` 면 화면에 `≈` 가 붙는 추정값입니다 |
| `linked` | bool | 한도 정보를 받아오고 있나. `false` 면 「연동 필요」 |
| `stateText` | string | 화면에 뜬 연동 상태 문구 |

### 3-3. `point` — 시점 단위

| 칸 | 타입 | 뜻 |
|---|---|---|
| `capturedAt` | 날짜시각 | 이 값을 읽은 시각(오프셋 포함) |
| `source` · `confidence` | string | 어디서 읽었나 · 얼마나 믿을 만한가 (`ProviderReading` 의 열거값) |
| `statusText` | string? | 머리줄 상태 문구. **표시 언어를 탑니다** — 판정에 쓰지 마십시오 |
| `session` · `week` | 아래 표 | 5시간 한도창 · 7일 한도창 |
| `modelWeeks[]` | `{label, percent, resetsAt}` | 모델별 주간 한도. 없으면 빈 배열 |
| `spending` | `{kind, consumed, ceiling, available, currency, cycleEndsAt}` | 초과분 사용액 또는 선불 잔액 |
| `cost` | 아래 표 | 비용·토큰 |
| `value` | `{ratio, grade, monthlyFeeUsd}` | 활용도. 구독료를 모르면 없음 |

**`session` · `week`** — 쓰지 않는 칸은 빠집니다.

| 칸 | 뜻 |
|---|---|
| `used` · `limit` | 쓴 양 · 한도 (서비스가 준 단위 그대로, 보통 토큰) |
| `percent` | 0~100. 화면의 `%` 와 같은 값입니다 |
| `resetsAt` | **한도가 풀리는 절대 시각.** 화면의 「5분 후 초기화 · 13:40」 이 이 값입니다 |
| `durationHours` | 한도창의 길이(시간). 세션 5, 주간 168 |

**`cost`** — 금액은 전부 **USD** 입니다.

| 칸 | 뜻 |
|---|---|
| `todayUsd` · `todayTokens` | 오늘 |
| `windowDays` | 팝업 기간 칩이 고른 날수(7 · 14 · 30 · 90 · 180 · 365) |
| `windowUsd` · `windowTokens` | 그 기간 합계 |
| `avgPerDayUsd` · `avgPerDayTokens` | 그 기간 ÷ `windowDays` |

**`value`** — `ratio` 는 구독료 대비 배수입니다(`2.5` = 2.5배). `grade` 는 화면에 뜬 등급 문구라 **언어를 탑니다** — 판정에는 `ratio` 를 쓰십시오.

### 3-4. `usage` — 기간 사용량 원자료

| 칸 | 뜻 |
|---|---|
| `rangeDays` · `from` · `to` | 담긴 기간 (`from`·`to` 는 `yyyy-MM-dd`, 이 PC 의 현지 날짜) |
| `byDayModel[]` | `{day, model, costUsd, tokens, input, output, cacheRead, cacheWrite}` |
| `byProgram[]` | `{program, costUsd, tokens}` — `claude-desktop` · `claude-vscode` · `cli` · `local-agent` · `unknown` |

- 팝업의 **일별 막대 · 모델 30일 · 토큰 유형 30일**은 전부 `byDayModel` 을 접은 것입니다 —
  날짜로 접으면 막대, 모델로 접으면 모델별, `input`~`cacheWrite` 를 더하면 토큰 유형이 됩니다.
- `tokens − (input+output+cacheRead+cacheWrite)` 가 화면의 **「유형 미상」** 입니다 — 유형 칸이 생기기 전에 쌓인 날이 여기 들어갑니다.
- 이 배열은 **기간을 자른 사본**입니다. 전체 이력(최대 400일)은 `%LOCALAPPDATA%\AiUsageMonitor\history\` 가 갖습니다.

## 4. `timeline\<key>\<YYYY-MM>.jsonl`

한 줄에 JSON 하나입니다. 파일은 **현지 시각 기준 월**로 갈립니다.

```jsonc
{"schemaVersion":1,"key":"claude-work","providerId":"claude:work","point":{ … }}
```

- `point` 는 3-3 과 **같은 모양**입니다.
- 값이 달라졌을 때만 줄이 늘어납니다 — 줄 사이 간격이 갱신 주기와 같지 않습니다.
- 앱을 다시 띄우면 직전 값과의 비교가 초기화돼 같은 값이 한 줄 더 들어갈 수 있습니다.

## 5. 읽는 쪽에 드리는 말

- **`schemaVersion` 을 먼저 보십시오.** 모르는 값이면 멈추는 쪽이 안전합니다.
- **모르는 칸은 무시하십시오.** 칸은 더 늘어날 수 있고, 그때 `schemaVersion` 은 올리지 않습니다.
- **`null` 인 칸은 아예 빠집니다.** 없는 것과 0 은 다릅니다.
- **`statusText` · `value.grade` · `account.plan` 은 표시 언어를 탑니다.** 기계 판정에는 숫자 칸을 쓰십시오.
- 날짜시각은 전부 **오프셋이 붙은 ISO 8601** 입니다. 날짜만 있는 칸(`from`·`to`·`day`)은 이 PC 의 **현지 날짜**입니다.
- 쓰는 중 읽을 수 있습니다 — `snapshot.json` 은 바꿔 끼우기라 안전하고, `jsonl` 은 **마지막 줄이 덜 쓰였을 수 있으니** 파싱 실패한 줄은 건너뛰십시오.

```powershell
# 예: 지금 계정별 세션 사용률과 초기화 시각
$s = Get-Content "$env:LOCALAPPDATA\AiUsageMonitor\data\snapshot.json" -Raw | ConvertFrom-Json
$s.accounts | ForEach-Object {
    '{0,-12} {1,5}% · 초기화 {2}' -f $_.account.displayName, $_.point.session.percent, $_.point.session.resetsAt
}
```
