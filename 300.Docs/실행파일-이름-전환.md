# 실행 파일 이름 전환 — `AiUsageMonitor.exe` → `AI-Usage-Monitor_JHJ.exe`

v1.1.0 에서 실행 파일 이름을 설치 파일과 같은 이름으로 바꿨습니다.
**이 문서는 2단계 전환이 끝날 때까지 지우지 않습니다** — 2단계에서 무엇을 걷어낼지가 여기 있습니다.

---

## 1. 왜 2단계인가

업데이트를 실제로 수행하는 쪽은 **지금 깔려 있는 구버전**입니다. v1.0.3 이하의
[StartupUpdateCoordinator.cs](../200.Source/costats.App/Services/Updates/StartupUpdateCoordinator.cs) 는

- 릴리스 자산 중 이름이 **`AiUsageMonitor-win-`** 으로 시작하는 zip 만 고르고,
- 그 zip 안에서 **`AiUsageMonitor.exe`** 라는 고정 파일명을 찾습니다.

둘 중 하나라도 어긋나면 구버전은 **업데이트를 영영 받지 못합니다.** 그래서 1단계에서는
**zip 이름을 그대로 두고, zip 안에 옛 이름 사본을 함께 넣습니다.**

## 2. 1단계에서 한 일 (v1.1.0)

| 바꾼 것 | 자리 |
|---|---|
| 실행 파일 이름 | `costats.App.csproj` 의 `AssemblyName` |
| 스테이징에서 exe 찾기 | `StartupUpdateCoordinator.TryFindStagedExecutable` — **새 이름 → 옛 이름** 순으로 본다 |
| 이름 상수 | 같은 파일 `ExecutableName` · `LegacyExecutableName` |
| 웹 설치 관리자 | `costats.Setup/Installer.cs` — `ExeName` 은 새 이름, `LegacyExeName` 추가. **설치 폴더 탐지와 프로세스 종료는 두 이름 모두** 본다 |
| 꾸러미 | `800.Deploy/publish.ps1` — zip 을 만들기 전에 **옛 이름 사본을 하나 더 넣는다** |
| 바로가기 복구 | `SelfInstaller.RefreshShortcutIfStale()` — 시작할 때 바로가기가 옛 exe 를 가리키면 다시 쓴다 |
| 시작 프로그램 복구 | `SettingsViewModel.SetStartupRegistryValue` 가 켜든 끄든 지금 exe 경로로 다시 쓴다 |
| 스크립트 | `Build-Exe.bat` · `release.ps1` — 종료 대상에 두 이름 모두 |

## 3. 바꾸지 않은 것 — 바꾸면 사용자 데이터·연결이 끊긴다

| 자리 | 값 | 바꾸면 |
|---|---|---|
| 데이터 폴더 | `%LOCALAPPDATA%\AiUsageMonitor\` | 설정 · 최대 400일 이력 · 계정 폴더 · 토큰 · 진단 동의가 전부 사라진 것처럼 보인다 |
| 자격 증명 키 | `AiUsageMonitor:` (`CredentialVault`) | 모든 계정 재로그인 |
| 업데이트 zip 이름 | `AiUsageMonitor-<rid>-v<버전>.zip` | 이미 배포된 버전이 이 이름으로만 다음 버전을 찾는다 |
| 웹 설치 자산 이름 | `AI-Usage-Monitor_JHJ_Setup.exe` | `latest/download` 고정 주소 · winget 매니페스트가 깨진다 |
| 시작 메뉴 바로가기 | `AI 통합 사용량 모니터.lnk` | 옛 바로가기가 안 지워지고 중복된다 |
| 시작 프로그램 값 이름 | `AiUsageMonitor` (Run · StartupApproved) | 작업 관리자 「시작 앱」에 유령 항목이 남는다 |
| 단일 인스턴스 이름 | `AiUsageMonitor` (뮤텍스·파이프) | 과도기에 옛·새 exe 가 서로를 못 알아봐 둘 다 뜬다 |
| 「프로그램 추가/제거」 키 | `…\Uninstall\AiUsageMonitor` | 옛 항목이 남고 제거 버튼이 없는 파일을 가리킨다 |
| winget 패키지 ID | `HyungJin.AiUsageMonitor` | 기존 winget 설치본이 업그레이드 대상에서 빠진다 |

## 5. 남은 흠

- 자동 업데이트로 이름이 바뀐 경우 **「프로그램 추가/제거」의 아이콘 경로**(`DisplayIcon`)가 옛 exe 를 가리킨 채 남습니다.
  아이콘만 비는 것이라 동작에는 지장이 없고, 웹 설치 관리자를 한 번 돌리면 고쳐집니다.
- 트레이 아이콘 「항상 표시」는 Windows 가 **실행 파일 경로로** 기억합니다 — 이름이 바뀌면 새 항목으로 취급돼
  한 번 다시 켜야 할 수 있습니다(설정 › 일반 「작업 표시줄에 아이콘 항상 표시」).
