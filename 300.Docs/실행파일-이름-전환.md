# 이름 전환 — `AiUsageMonitor` → `JHJ_AI-Usage-Monitor`

v1.0.5 에서 **실행 파일 · 데이터 폴더 · 설치 폴더 · 등록 이름**을 설치 파일과 같은 이름으로 바꿨습니다.
**이 문서는 2단계가 끝날 때까지 지우지 않습니다** — 무엇을 언제 걷어낼지가 여기 있습니다.

---

## 1. 딱 하나 바꾸지 않은 것 — 업데이트 zip 이름

```text
AiUsageMonitor-<rid>-v<버전>.zip        ← 옛 이름 그대로
```

업데이트를 **실제로 수행하는 쪽은 지금 깔려 있는 구버전**입니다. v1.0.4 이하는

- 릴리스 자산 중 이름이 **`AiUsageMonitor-win-`** 으로 시작하는 zip 만 고르고,
- 그 zip 안에서 **`AiUsageMonitor.exe`** 라는 고정 파일명을 찾습니다.

그래서 zip 이름은 그대로 두고, **zip 안에 옛 이름 exe 사본을 함께 넣습니다.**
네 곳이 항상 같은 이름이어야 합니다 — `publish.ps1` · `release.ps1` · `ReleaseClient.cs` · `StartupUpdateCoordinator.cs`.

⛔ **이 이름을 바꾸면 기존 설치본은 수동 재설치 말고는 길이 없습니다.**

## 2. 바꾼 것

| 무엇 | 전 | 후 |
|---|---|---|
| 실행 파일 | `AiUsageMonitor.exe` | `JHJ_AI-Usage-Monitor.exe` |
| 데이터 폴더 | `%LOCALAPPDATA%\AiUsageMonitor\` | `%LOCALAPPDATA%\JHJ_AI-Usage-Monitor\` |
| 설치 폴더 | 〃 `\app` | 〃 `\app` |
| 시작 프로그램 값 이름 | `AiUsageMonitor` | `JHJ_AI-Usage-Monitor` |
| 자격 증명 키 | `AiUsageMonitor:` | `JHJ_AI-Usage-Monitor:` |
| 단일 인스턴스 이름 | `AiUsageMonitor` | `JHJ_AI-Usage-Monitor` |
| 「프로그램 추가/제거」 키 | `…\Uninstall\AiUsageMonitor` | `…\Uninstall\JHJ_AI-Usage-Monitor` |
| 웹 설치 관리자 exe | `AiUsageMonitor-Setup.exe` | `JHJ_AI-Usage-Monitor-Setup.exe` |
| winget 패키지 ID | `HyungJin.AiUsageMonitor` | `HyungJin.JHJ_AI-Usage-Monitor` |
| 로그 파일 접두 | `AiUsageMonitor-.log` | `JHJ_AI-Usage-Monitor-.log` |
| 작업 관리자 표시명 | `AI 통합 사용량 모니터` | `JHJ AI 통합 사용량 모니터` (`AssemblyTitle`) |
| 「프로그램 추가/제거」 이름 | 〃 | 〃 |
| 시작 메뉴 바로가기 | `AI 통합 사용량 모니터.lnk` | `JHJ AI 통합 사용량 모니터.lnk` |
| winget 표시명 | `AI Usage Monitor` | `JHJ AI Usage Monitor` |

**바뀌지 않은 것** — 앱 창 안의 문구(팝업 제목·설정 머리글. 폭이 좁아 `JHJ` 를 더하면 잘린다) ·
설치 파일 자산 이름 `JHJ_AI-Usage-Monitor_Setup.exe`.

## 3. 기존 사용자를 데려오는 장치

| 장치 | 어디 | 하는 일 |
|---|---|---|
| 세대별 이사 | `LegacyMigration.Run()` | `costats-jhj` → `AiUsageMonitor` → `JHJ_AI-Usage-Monitor` 를 **차례로** 옮긴다. 데이터 폴더와 시작 프로그램 등록(Run + StartupApproved)이 대상 |
| 설치 폴더 제외 | 같은 곳 `InstallFolder` | ⚠️ **데이터 폴더 안에 설치 폴더(`app`)가 있다.** 통째로 옮기면 지금 돌고 있는 exe 가 잠겨 **이사 전체가 실패**한다 — `app` 만 빼고 항목별로 옮긴다 |
| 자격 증명 인계 | `CredentialVault.TakeOverLegacy` | 새 이름으로 읽히지 않으면 옛 이름에서 읽어 **새 이름으로 옮기고 옛 항목을 지운다.** 사용자는 다시 로그인하지 않는다 |
| 옛 exe 호환 | `StartupUpdateCoordinator.LegacyExecutableName` · `Installer.LegacyExeName` | 스테이징·설치 폴더에서 **새 이름 다음에 옛 이름도** 본다 |
| 옛 이름 사본 | `publish.ps1` | zip 을 만들기 전에 `AiUsageMonitor.exe` 사본을 하나 더 넣는다 |
| 바로가기 복구 | `SelfInstaller.RefreshShortcutIfStale()` | 시작할 때 바로가기가 옛 exe 를 가리키면 지금 exe 로 다시 쓴다 |
| 시작 프로그램 경로 복구 | `SettingsViewModel.SetStartupRegistryValue` | 켜든 끄든 지금 exe 경로로 다시 쓴다 |
| 유령 항목 정리 | `LegacyMigration.CleanOrphanStartupApproved` | Run 값이 없는 「시작 앱」 기록을 지운다 |

## 5. 남은 흠 — 기존 설치본에서 한 번씩 나타날 수 있는 것

| 증상 | 왜 | 어떻게 풀리나 |
|---|---|---|
| 옛 `%LOCALAPPDATA%\AiUsageMonitor\app` 폴더가 남는다 | 이사에서 `app` 을 제외한다 | 웹 설치 관리자를 한 번 돌리면 새 자리에 깔린다. 옛 폴더는 손으로 지워도 된다 |
| 「프로그램 추가/제거」의 제거 버튼이 동작하지 않는다 | 옛 항목의 `UninstallString` 이 이사해 버린 `AiUsageMonitor-Setup.exe` 를 가리킨다 | 새 웹 설치 관리자를 한 번 돌리면 새 항목이 등록된다 |
| 트레이 「항상 표시」가 풀린다 | Windows 가 **실행 파일 경로로** 기억한다 | 설정 › 일반에서 다시 켠다 |
| winget 업그레이드가 끊긴다 | 패키지 ID 가 바뀌었다 | 아직 공식 저장소에 제출한 적이 없어 **실제 피해는 없다.** 새 ID 로 처음 제출하면 된다 |
